# 薪酬同步工具 — 使用说明

[🌐 English Documentation](README.md)


## 一、项目概述

本工具用于将北森 iTalent HR 系统中的薪酬数据，自动同步到飞书多维表格。

每天定时运行（默认 22:32），自动完成以下三个表的数据同步：

| 同步顺序 | 飞书表名 | 对应脚本 | 数据来源 | 同步规则 |
|---------|---------|---------|---------|---------|
| 1 | 1-工资标准 | `sync_wage_standard.py` | 全部薪资档案 | 按工号匹配，有变化就更新 |
| 2 | 2-工资数据 | `sync_table1.py` | 全部薪资档案 | 按工号+生效日期增量新增，不覆盖 |
| 3 | 3-调薪记录表 | `sync_table3.py` | 全部薪资档案 | 相邻记录配对新增，不覆盖 |

---

## 二、环境要求

- **操作系统**：Windows 10 或以上
- **Python**：3.10 或以上版本
- **网络**：需能访问北森 HR 系统和飞书开放平台

## 三、首次安装

### 步骤 1：安装 Python（如已安装可跳过）

1. 访问 https://www.python.org/downloads/
2. 下载最新版 Python（推荐 3.12）
3. 安装时 **务必勾选** `Add Python to PATH`
4. 安装完成后，打开 PowerShell，输入 `python --version` 确认安装成功

### 步骤 2：获取项目文件

```bash
git clone https://github.com/your-username/italent-salary-sync.git
cd italent-salary-sync
```

或者直接下载 ZIP 解压到本地。

### 步骤 3：运行初始化脚本

1. 打开项目文件夹
2. **双击 `setup.bat`**
3. 等待自动安装完成（首次安装 Playwright 浏览器约需 2-5 分钟）
4. 安装成功后会看到 ✅ 提示

> **如果 setup.bat 执行失败**，也可以手动安装：
> ```
> pip install -r requirements.txt
> python -m playwright install chromium
> ```

### 步骤 4：修改配置

1. 将 `config.example.py` 复制一份并重命名为 `config.py`
2. 用记事本打开 `config.py`，填入真实的配置值：

```python
# HR 系统（北森 iTalent）
HR_LOGIN_URL = "https://your-company.italent.cn/Login"
HR_USERNAME  = "your_email@company.com"
HR_PASSWORD  = "your_password"

# 飞书应用凭证
FEISHU_APP_ID     = "your_feishu_app_id"
FEISHU_APP_SECRET = "your_feishu_app_secret"

# 多维表格 ID（URL 中 base/ 后面的字符串）
FEISHU_BASE_ID    = "your_base_id"

# 各表的 table_id
FEISHU_TABLE1_ID  = "your_table1_id"
FEISHU_TABLE2_ID  = "your_table2_id"
FEISHU_TABLE3_ID  = "your_table3_id"

# 同步完成后接收飞书通知的用户 ID
FEISHU_NOTIFY_USER_IDS = ["user_id_1", "user_id_2"]

# 定时执行时间（24小时制）
SYNC_TIME = "22:32"
```

> **重要提示**：
> - `config.py` 已被 `.gitignore` 排除，不会被提交到 Git
> - HR 账号需要有北森薪酬社保模块的访问权限
> - 飞书应用需要有多维表格读写权限和消息发送权限

## 四、运行方式

### 方式 A：手动执行单个表（测试用）

打开 PowerShell，进入项目目录后执行：

```powershell
cd 项目路径
python sync_wage_standard.py    # 只同步表1（1-工资标准）
python sync_table1.py           # 只同步表2（2-工资数据）
python sync_table3.py           # 只同步表3（3-调薪记录表）
```

首次运行建议逐个表测试，确认无误后再启动定时服务。

### 方式 B：启动定时同步服务

**双击 `start_service.bat`**，服务会在后台持续运行，每天 22:32 自动执行全部三个表的同步。

或者在 PowerShell 中运行：
```powershell
cd 项目路径
python main.py
```

> **注意**：
> - 关闭 PowerShell 窗口或 bat 窗口会停止服务
> - 如果电脑关机或休眠，服务也会停止，需要重新启动
> - 建议将电脑设置为不自动休眠，并将 `start_service.bat` 加入开机启动项

### 方式 C：加入开机自启动（推荐）

**双击 `auto_start_setup.bat`**，按提示选择「设置开机自启动」即可。

脚本会自动在 Windows 启动文件夹中创建快捷方式，开机登录后同步服务会自动在后台启动（窗口最小化，不影响日常使用）。

如需取消自启动，再次双击 `auto_start_setup.bat`，选择「移除开机自启动」。

## 五、三个表的详细逻辑

### 表1：1-工资标准（sync_wage_standard.py）

**作用**：为每个员工维护一行汇总数据，包含当前工资、试用期工资、转正后工资。

**数据来源**：HR 系统「全部薪资档案」

**字段说明**：

| 飞书字段 | 数据来源 | 说明 |
|---------|---------|------|
| 工号 | 工号 | 匹配键 |
| 姓名 | 员工 | — |
| 部门 | 部门 | — |
| 职务 | 职务 | — |
| 币种 | offer币种 | — |
| 【当前薪资包】 | 生效日期最晚的记录的薪资包 | — |
| 【当前】固定工资 | 生效日期最晚的记录 | 日薪包=实习生日薪×22 |
| 【当前】绩效标准 | 生效日期最晚的记录 | 月度绩效基数，空则季度÷3 |
| 【当前】奖金基数 | 生效日期最晚的记录 | 月度奖金基数，空则季度÷3 |
| 【试用期】薪资包 | 变动原因=「入职定薪」的记录 | 无则为空 |
| 【试用期】固定工资 | 变动原因=「入职定薪」的记录 | 日薪包=实习生日薪×22 |
| 【试用期】奖金基数 | 变动原因=「入职定薪」的记录 | — |
| 【转正后】薪资包 | 变动原因=「转正调薪」的记录 | 无则为空 |
| 【转正】固定工资 | 变动原因=「转正调薪」的记录 | 日薪包=实习生日薪×22 |
| 【转正】绩效标准 | 变动原因=「转正调薪」的记录 | 月度绩效基数，空则季度÷3 |
| 【转正】奖金基数 | 变动原因=「转正调薪」的记录 | — |

**同步规则**：按工号匹配，已有记录对比全部字段，有变化则更新；不存在则新增。

---

### 表2：2-工资数据（sync_table1.py）

**作用**：记录每个员工每一条薪资历史（同一员工可有多行）。

**数据来源**：HR 系统「全部薪资档案」

**字段说明**：

| 飞书字段 | HR来源列 | 特殊逻辑 |
|---------|---------|---------|
| 工号 | 工号 | — |
| 姓名 | 员工 | 读 `.staff-name` 元素 |
| 部门 | 部门 | — |
| 职务 | 职务 | — |
| 币种 | offer币种 | — |
| 固定工资 | 基本工资 | 日薪包=实习生日薪×22 |
| 绩效标准 | 月度绩效基数 | 空则季度绩效基数÷3 |
| 奖金基数 | 月度奖金基数 | 空则季度奖金基数÷3 |
| 薪资包 | 薪资包 | — |
| 变动原因 | 变动原因 | — |
| 生效日期 | 生效日期 | 转为 Unix 时间戳（毫秒） |

**同步规则**：匹配键 =「工号 + 生效日期」，已存在则跳过，不存在则新增。只增不改，永不覆盖。

---

### 表3：3-调薪记录表（sync_table3.py）

**作用**：记录每次调薪的前后对比（调前工资 vs 调后工资）。

**数据来源**：HR 系统「全部薪资档案」

**生成逻辑**：
- 按工号分组，组内按生效日期排序
- 相邻两条记录配对：早的=调前，晚的=调后
- 3条记录 → 2行调薪记录，N条 → N-1行
- 只有1条记录的员工跳过

**字段说明**：

| 飞书字段 | 数据来源 | 说明 |
|---------|---------|------|
| 工号/姓名/部门/职务/币种 | 调后记录 | — |
| 变动原因 | 调后记录的变动原因 | — |
| 【调前】薪资包/固定工资/绩效标准/奖金基数 | 生效日期较早的记录 | 固定工资等计算逻辑同上 |
| 【调后】薪资包/固定工资/绩效标准/奖金基数 | 生效日期较晚的记录 | 固定工资等计算逻辑同上 |
| 生效日期 | 调后记录的生效日期 | Unix 时间戳（毫秒） |

**同步规则**：匹配键 =「工号 + 调后生效日期」，已存在则跳过，不存在则新增。只增不改。

## 六、通用计算规则

以下规则在三个表中保持一致：

| 字段 | 计算方式 |
|------|---------|
| 固定工资 | 薪资包包含「日薪」→ 实习生日薪 × 22；否则取基本工资 |
| 绩效标准 | 优先取月度绩效基数；若为空，取季度绩效基数 ÷ 3 |
| 奖金基数 | 优先取月度奖金基数；若为空，取季度奖金基数 ÷ 3 |
| 生效日期 | 写入飞书时转为 Unix 时间戳（毫秒） |

## 七、同步完成通知

每次定时同步完成后，系统会通过飞书应用向指定用户发送通知消息，内容包括：

- 同步时间
- 每个表的同步结果（新增/更新/跳过的条数）
- 如有同步失败，会显示错误原因

通知示例：

```
{表格名称}多维表格数据同步完成

同步时间：2026-06-04 22:35

✅ 1-工资标准：新增 5 条，更新 3 条，跳过 53 条
✅ 2-工资数据：新增 2 条，跳过 65 条
✅ 3-调薪记录表：新增 1 条，跳过 5 条

如有异常请查看日志文件 logs/sync.log
```

如需修改通知接收人，编辑 `config.py` 中的 `FEISHU_NOTIFY_USER_IDS` 列表。

## 九、日志查看

运行日志保存在 `logs/sync.log`，可用记事本打开查看。

日志中的关键信息：

| 日志内容 | 含义 |
|---------|------|
| `开始同步 [1-工资标准]` | 表1同步开始 |
| `HR 原始数据共 XX 行` | 从HR系统读到的总记录数 |
| `新增: XX 条` | 本次新写入飞书的记录数 |

| `同步完成` | 该表同步成功结束 |
| `同步失败` | 出错，后面会有具体错误信息 |

## 十、常见问题排查

### Q1：setup.bat 提示「未检测到 Python」
**A**：确认 Python 已安装且勾选了 `Add Python to PATH`。安装后需要关闭并重新打开 PowerShell 窗口。

### Q2：登录失败
**A**：检查 `config.py` 中的 `HR_USERNAME` 和 `HR_PASSWORD` 是否正确。该账号需要有北森薪酬社保模块的访问权限。

### Q3：HR 系统未返回任何数据
**A**：可能是页面结构变化或网络超时。将 `hr_client.py` 中的 `headless=True` 临时改为 `headless=False`，重新运行可以看到浏览器操作过程，便于定位问题。

### Q4：飞书写入失败
**A**：检查以下几点：
- `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET` 是否正确
- 飞书应用是否有多维表格的读写权限（`bitable:app`、`bitable:record:write`）
- `FEISHU_BASE_ID` 和各 `TABLE_ID` 是否与实际表格一致

### Q5：数据条数不对（应该67条但只读到55条）
**A**：说明「全部薪资档案」标签没有成功切换。查看日志中是否有 `全部档案视图: ✅`。如果没有，可能需要调整等待时间。

### Q6：想修改定时执行时间
**A**：打开 `config.py`，修改 `SYNC_TIME = "22:32"` 为你想要的时间（24小时制），保存后重启 `main.py`。

### Q7：同步完成但没收到飞书通知
**A**：检查以下几点：
- `config.py` 中的 `FEISHU_NOTIFY_USER_IDS` 是否填写了正确的飞书用户 ID
- 飞书应用是否开通了 `im:message` 消息发送权限
- 查看日志中是否有「飞书通知发送失败」的错误信息

### Q8：电脑关机后服务停了怎么办
**A**：双击 `auto_start_setup.bat`，设置开机自启动。之后每次开机登录会自动启动同步服务。

## 十一、飞书应用权限配置

如果需要配置新的飞书应用，需要开通以下权限：

1. 登录飞书开放平台（https://open.feishu.cn）
2. 进入应用管理，找到对应应用
3. 在「权限管理」中开通：
   - `bitable:app` — 访问多维表格
   - `bitable:app:readonly` — 读取多维表格记录
   - `bitable:record:write` — 写入多维表格记录
   - `im:message` — 发送消息（用于同步完成通知）
4. 在多维表格的「高级权限」中，将该应用添加为协作者

## 十二、北森 HR 系统页面注意事项

> ⚠️ **重要：请勿修改北森薪资档案页面的列配置**

本工具通过读取页面表格的列顺序来识别各字段数据。如果在北森 HR 系统中对「最新薪资档案」或「全部薪资档案」的列表做了以下操作，**可能导致脚本读取数据错乱或失败**：

- **删除列**：删除任何一列会导致后续所有列的位置偏移，字段映射错误
- **隐藏列**：同删除，会改变可见列的顺序
- **调整列顺序**：把列拖动到其他位置，会导致数据写入到错误的字段
- **向右滚动过多列**：表格采用虚拟渲染，超出视口的列可能无法被脚本读取

当前脚本依赖的列顺序（从左到右）：

```
员工 | 工号 | 部门 | 职务 | 生效日期 | 薪资包 | offer币种 | 变动原因 |
基本工资 | 月度奖金基数 | 季度绩效基数 | 季度奖金基数 | 月度绩效基数 |
实习生日薪 | 操作
```

如果因业务需要必须调整列配置，请同步通知开发人员修改脚本中的字段映射逻辑。

## 十三、安全提醒

- `config.py` 中包含 HR 系统密码和飞书应用密钥，属于敏感信息
- 请勿将 `config.py` 通过邮件、微信等方式分享
- 如需在多台电脑部署，每台电脑应使用各自的 HR 账号
- 建议定期更换 HR 系统密码，更换后同步修改 `config.py`
